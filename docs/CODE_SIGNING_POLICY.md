# Code signing policy

Project: **Code-Prüfer** – <https://github.com/BernhardGoetz/Entwicklung-test>
License: [MIT](../LICENSE)

Free code signing provided by [SignPath.io](https://about.signpath.io/), certificate by
[SignPath Foundation](https://signpath.org/).

## What is signed

- Only the Windows release artifacts of this project, built by the GitHub Actions
  workflow [`.github/workflows/release.yml`](../.github/workflows/release.yml) in this
  repository on GitHub-hosted runners, from the protected release branch `qas`. Nothing
  built on a developer machine is ever signed.
- Every build first goes through a QA stage (test-signing certificate only). The
  release-signing certificate is used only after the build has been manually accepted
  by an approver (GitHub environment `production`), and only for the exact files that
  were tested.
- Signed files (all built from the source code in this repository):
  - `code-pruefer.exe` – the application (Rust/Tauri, `cargo build --release`),
  - `uninstall.exe` – the uninstaller, generated by NSIS from
    [`src-tauri/windows/installer.nsi`](../src-tauri/windows/installer.nsi),
  - `Code-Pruefer_<version>_x64-setup.exe` – the NSIS installer.
- Third-party ("upstream") binaries shipped in the installer are **not** signed with the
  project certificate unless SignPath Foundation has explicitly approved it:
  the llama.cpp runtime (`llama/llama-server.exe`, `llama/*.dll`, taken unmodified from
  the official [llama.cpp release](https://github.com/ggml-org/llama.cpp/releases),
  version and SHA-256 pinned in
  [`scripts/fetch-llama-server.sh`](../scripts/fetch-llama-server.sh)) and the NSIS
  plugin DLLs. The Microsoft Visual C++ runtime DLLs are shipped with their original
  Microsoft signature and are never re-signed.
- The artifact configuration used in SignPath is versioned in
  [`.signpath/artifact-configurations/`](../.signpath/artifact-configurations/).
- macOS builds are not covered by this policy (they are signed with an Apple Developer ID,
  if at all).

## Release process

1. A reviewer reviews all changes, including the build scripts and workflows
   (`.github/`, `scripts/`, `src-tauri/`).
2. The reviewed state is pushed to the release branch `qas`. GitHub Actions builds the
   application and the installer and publishes a QA pre-release (test-signed via
   SignPath's test-signing policy).
3. After testing, an approver accepts the QA build in GitHub (environment
   `production`). The workflow then submits the same, unchanged binaries to SignPath's
   release-signing policy (origin-verified through the GitHub Actions integration).
4. An approver checks each signing request in SignPath (repository, branch, commit,
   workflow run) and approves it.
5. The workflow verifies all Authenticode signatures, checks that the release installer
   differs from the tested QA installer only in its signatures, and creates the version
   tag and a draft release with `SHA256SUMS.txt` and a GitHub build provenance
   attestation, which is then published by the author.

## Privacy policy

Code-Prüfer runs entirely on the user's computer. It has no user accounts, no telemetry,
no analytics and no crash reporting, and it does not send code, tasks, test cases or any
other user data to the author or to third parties.

The only network connections the application makes are:

- **AI model download (optional, on user request):** when the user clicks the download
  button in the model manager, the selected model file is downloaded from
  `huggingface.co` (and its CDN hosts `*.huggingface.co` / `*.hf.co`). Only a regular
  HTTPS file download is performed; no user data is sent. Hugging Face's privacy policy
  applies: <https://huggingface.co/privacy>.
- **Runner images (container engine):** the user's container engine (Docker or Podman)
  pulls the runner images from the GitHub Container Registry `ghcr.io` when they are not
  yet installed and are not loaded from the installer, or when the user clicks
  "Images aktualisieren". GitHub's privacy statement applies:
  <https://docs.github.com/site-policy/privacy-policies/github-general-privacy-statement>.
- **Update check (installed versions only, can be turned off):** at most once a day
  (default; weekly or never in the settings) and when the user clicks "Jetzt nach Updates
  suchen", the app downloads
  `https://github.com/bernhardgoetz/entwicklung-test/releases/latest/download/latest.json`
  over HTTPS, and on "Jetzt aktualisieren" the installer it names from the same GitHub
  release. No user data is sent (GitHub sees the IP address and a generic user agent);
  every update is verified against the project's update signing key before it is
  installed. Builds without that key and the portable Windows version never check.
  GitHub's privacy statement applies:
  <https://docs.github.com/site-policy/privacy-policies/github-general-privacy-statement>.
- **Podman virtual machine (only if the user chose Podman and lets the app start it):**
  on the first start the app runs `podman machine init`, which makes Podman download its
  virtual machine image once from the Podman project's servers (several hundred MB). The
  app itself sends nothing; Podman's own behaviour and the policies of its image hosts
  apply.
- **Container engine installation (Windows installer, only on request):** if the chosen
  engine is missing and the user agrees, the installer runs `winget install` for Docker
  Desktop or Podman. winget contacts the Microsoft winget source and downloads the
  installer from the vendor (Docker, or the Podman project on GitHub). Microsoft's,
  Docker's and GitHub's privacy statements apply.
- **Local only:** the app talks to the local container engine (socket or named pipe) and
  to the bundled AI runtime on `127.0.0.1` (started with `--offline`). User code is
  executed in containers **without network access**.
- Links to the Docker and Podman websites and to the project's release page are opened in
  the user's browser only when the user clicks them.
- Docker Desktop and Podman, once started, may contact their vendors according to their
  own settings (for example update checks); this is outside Code-Prüfer.
